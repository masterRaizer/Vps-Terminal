# Vps Terminal SSH

Настольный SSH/SFTP-клиент для Windows: Electron + React + TypeScript + Vite.

## Запуск

```bash
npm install
npm run dev        # режим разработки
npm run build      # сборка в out/
npm test           # интеграционные тесты SSH (встроенный ssh2-сервер)
npm run typecheck
```

## Специальные возможности

Запуск с `--a11y` (или переменной `VTS_A11Y=1`) включает полное дерево специальных возможностей: экранный диктор и средства автоматизации Windows видят все кнопки и поля по именам.

## Сборка .exe

```bash
npm run dist:win     # release/Vps-Terminal-SSH-Setup-<версия>.exe и …-portable.exe
```

GitHub Actions (`.github/workflows/build.yml`): тесты на Ubuntu → сборка на windows-latest (установщик + portable, smoke-тест упакованного приложения) → артефакт `vps-terminal-ssh-windows`; при теге `v*` — релиз с .exe. Отдельно собирается и проверяется Docker-образ sync-server.

## Архитектура

| Слой | Где | Что делает |
|---|---|---|
| main | `src/main` | ssh2-соединения (`SshManager`), проверка ключа сервера, валидация IPC, CSP |
| preload | `src/preload` | `contextBridge` → `window.api`, без доступа к Node из renderer |
| renderer | `src/renderer` | React 19 + zustand, xterm.js (fit / webgl / search) |
| shared | `src/shared/ipc.ts` | единый контракт IPC и типы |

Безопасность: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, запрет навигации и новых окон, отказ во всех permission-запросах, CSP. Пароль передаётся в main один раз для рукопожатия и нигде не сохраняется.

## Данные

- Каталог хостов и групп — SQLite (`better-sqlite3`, файл `vault.db` в папке профиля приложения).
- Пароли — только в диспетчере учётных данных Windows через `keytar` (служба «Vps Terminal SSH»). В интерфейс сохранённый пароль не попадает: main сам достаёт его при подключении.
- Если хранилище учётных данных недоступно, пароли живут в памяти до закрытия приложения, и интерфейс об этом предупреждает.
- Вход: пароль или SSH-агент (OpenSSH-агент Windows). Вход по ключу — шаг 3.

### Импорт hosts.json

```json
[
  { "label": "web-01", "address": "203.0.113.10", "port": 22, "username": "root", "group": "Prod", "tags": ["eu"], "key": "id_ed25519" }
]
```

Принимаются также поля `host`/`hostname` и `user`; паролей файл не содержит. Дубликаты (адрес+порт+пользователь) пропускаются. Поле `key` помечает хост как «вход по ключу»; сами ключи импортируются на шаге 3.

## Ключи и профили доступа

- Импорт файлов или целой папки (`~/.ssh`, `keys\`): OpenSSH, PEM, PuTTY .ppk v2; рядом лежащий `.pub` подхватывается. Хосты из `hosts.json` с полем `key` автоматически привязываются к ключу с тем же именем файла.
- Генерация ED25519 / RSA 2048–4096, по желанию с парольной фразой.
- Приватные ключи хранятся в базе зашифрованными (AES-256-GCM); 32-байтный ключ шифрования лежит в диспетчере учётных данных Windows (туда не помещается RSA-4096 целиком — лимит ~2,5 КБ на запись). Парольные фразы — по желанию тоже там.
- Профиль доступа = пользователь + пароль и/или ключ; назначается хостам и нодам Remnawave.

## Remnawave

«Хосты» → «Remnawave»: адрес панели и API-токен (Настройки → API-токены) либо логин/пароль администратора — тогда приложение само получает токен сессии через `/api/auth/login`. «Синхронизировать» создаёт группу с нодами из `/api/nodes`: имя, адрес, теги, флаг страны. Повторная синхронизация обновляет имена/адреса и не трогает ваши правки (порт, профиль, заметки, страну вручную); ноды, исчезнувшие из панели, получают тег «нет в панели». Секреты панели — в диспетчере учётных данных.

## Флаги стран

Страна берётся из ноды Remnawave; иначе из названия хоста («VPS NL», «[AE]», «Амстердам», «финка»…); иначе по IP по встроенной офлайн-базе геолокации IP to Country Lite от [DB-IP.com](https://db-ip.com) (CC BY 4.0; адреса никуда не отправляются); её всегда можно выбрать вручную. Флаги — flag-icons (MIT). Таблицы GeoIP собираются скриптом `npm run geoip` (запускается автоматически перед dev/build/test).

## Сниппеты

Команды с переменными `{{имя}}` и `{{имя:по умолчанию}}`; перед вставкой появляется форма. Вставка или выполнение — из правой панели терминала. Стартовый сниппет хоста выполняется после входа. История — только команды, отправленные сниппетами (набранное вручную не записывается: там бывают пароли).

## Проброс портов

Локальный (`-L`), удалённый (`-R`) и динамический SOCKS5 (`-D`). Каждое правило — отдельное SSH-соединение с учётными данными хоста (нужен сохранённый пароль, ключ или агент). По умолчанию слушается только 127.0.0.1; другой адрес помечается предупреждением. Правила можно запускать вместе с приложением; число активных туннелей — в строке состояния.

## Известные хосты

Trust-on-first-use: новый ключ сервера подтверждается и сохраняется; совпадающий принимается молча; изменившийся — красное предупреждение со старым и новым отпечатком, по умолчанию подключение отменяется. Импорт OpenSSH `known_hosts` (хешированные имена пропускаются).

## Синхронизация

«Синхронизация» в левом меню: адрес своего сервера, токен и мастер-пароль. Всё хранилище — хосты, группы, ключи (с приватной частью), профили, пароли, сниппеты, туннели, известные хосты — шифруется на клиенте (scrypt N=2^17 + AES-256-GCM, заголовок KDF аутентифицирован). Сервер (`sync-server/`, Node без зависимостей, Docker) хранит только зашифрованный файл и номер версии. Слияние — по записям: побеждает более свежая правка, удаления передаются как tombstone-метки; при одновременной записи сервер отвечает 409, клиент объединяет и повторяет. Изменения отправляются через ~2,5 с после правки, приём — при запуске и каждые 5 минут.

## Интерфейс

- Верхняя полоса: меню, вкладка «Хранилище», вкладка SFTP, вкладки SSH-сессий с цветом статуса, «+» — новое подключение.
- Хранилище: левое меню (Хосты, Ключи, Проброс портов, Сниппеты, Известные хосты, Журнал), строка поиска/подключения (`ssh user@host -p 22`, Ctrl+K), сетки карточек, редактор в выезжающей правой панели.
- Сессия: терминал во всё окно + правая панель (поиск Ctrl+Shift+F, действия, сниппеты, история, темы и размер шрифта).
- SFTP: две панели — локальная и удалённая.
- Палитра интерфейса — тёмно-синяя (`#151a2b` / `#1d2134` / карточки `#282d41`, акцент `#1d8cf8`); 35 тем терминала, разделённых на тёмные и светлые: свои (Navy Green, Navy Classic, Paper, Ember, Glacier, Phosphor, Cinder), Catppuccin Mocha (по умолчанию) и открытые схемы из [iTerm2-Color-Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes) (MIT): Kanagawa, Flexoki, Everforest, Solarized, Dracula, Monokai, Nord, Gruvbox, Material, Homebrew, Grass, Man Page, Novel, Ocean, Pro, Red Sands, Apple Classic, Basic. Шрифт по умолчанию — встроенный Source Code Pro 14px (OFL), выбор Cascadia Mono / JetBrains Mono / Consolas; история прокрутки 40 000 строк.
- Редактор хоста: адрес с цветной плиткой, название, группа, теги, режим Backspace (^? / ^H), порт, учётные данные (пароль / SSH-агент; ключ — шаг 3), проброс агента, переменные окружения, тема терминала для хоста, заметки. Изменения сохраняются автоматически.
